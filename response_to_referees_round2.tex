\section*{Editorial overview}

We thank the editor for inviting a revision rather than adopting Reviewer~3's
recommendation of rejection. We have treated every technically supportable
request in that report seriously. The revision is extensive:

\begin{itemize}
  \item The paper retains its exact submitted title and its pre--Reviewer~3
  general framing. DiRe is a dimensionality--reduction framework for a
  user--specified target dimension $d$, including non--visual dimensions used
  in subsequent analysis. The value $d=2$ identifies the configuration of the
  visual benchmark figures; it does not redefine the method.
  \item The introduction now states that global organization in both tSNE and
  UMAP is initialization--dependent and that modern FFT/interpolation tSNE
  implementations scale beyond the original exact formulation.
  \item The relation to tSNE and UMAP is made explicit. We do not claim that
  PCA initialization, spectral initialization, or the kernel family is new.
  The revised novelty statement identifies the particular force law, unweighted
  attraction graph, bounded random point--index repulsion, separately
  ablatable initialization/refinement stages, and evaluation protocol.
  \item The implementation and scaling section now states the point that the
  report gets factually wrong: default DiRe does not compute all--pairs
  repulsion. With fixed neighbor count, negative ratio, output dimension, and
  iteration count, the layout cost is linear in the number of points.
  \item We added PCA, separate same--GPU scaling panels, a separate CPU
  reference panel containing openTSNE and \texttt{umap-learn}, and a
  PCA-versus-spectral initialization ablation.
  \item We added two full public large--data tests: 1,306,127 10x mouse-brain
  cells and 723,457 arXiv paper embeddings. All reducers receive the same
  prepared rows, and the suite records cold and synchronized steady timings,
  peak incremental NVML device--memory use, failures, parameters, package
  versions, and exact diagnostic row-index subsets.
  \item We condensed the metric presentation, added a direct results narrative,
  and engaged the earlier topological and rank--based evaluation literature.
  The large-data topology analysis now reports exact diameter-normalised
  bottleneck distances as well as the historical Betti--DTW score, retains
  \TopologySubsetCount{} independently seeded, fixed 4,000--row topology
  subsets shared by the input and every embedding, and includes a separately
  labelled robust-scale sensitivity calculation. DiRe's default
  \texttt{init="pca"} pathway is shown
  alongside a one-factor spectral-initialisation control and the
  source-predeclared topology preset; neither sensitivity variant is
  substituted for the default. The manuscript now states the backend dispatch:
  the H100 cuVS path uses cuML PCA at most 100 input features and cuML
  TruncatedSVD above 100.
\end{itemize}

These changes should not be read as agreement with the factual accuracy or
proportionality of the rejection recommendation. Reviewer~3's report combines
useful requests with overstatements, conjectures presented as findings, and at
least one central claim that is directly contradicted by the implementation.
We distinguish those categories below.

\section*{Reviewer 3: summary recommendation}

\reviewcomment{I recommend rejection. The manuscript does not provide a clear
justification for DIRe's existence relative to t-SNE and UMAP \ldots}

\response The recommendation is not supported by the report's own mixture of
correctable presentation requests and factually disputed premises. Similarity
to a broad algorithmic family is not nonexistence of a contribution; tSNE and
UMAP themselves occupy different points in a shared attraction--repulsion
family. A serious novelty assessment must compare objectives, graph weights,
sampling rules, force gradients, initialization/refinement interfaces, and
observed tradeoffs. The phrase ``slightly modified expressions'' does not
perform that comparison.

More importantly, the recommendation relies on claims that are demonstrably
incorrect: default DiRe does not perform all--pairs repulsion; UMAP's standard
optimization is not dominated by enumerating every point pair; and the archived
same--GPU timings do not show DiRe to be the slowest of all three GPU methods.
The all--pairs description is, in the literal technical sense relevant here, a
\emph{hallucinated implementation premise}: it describes an operation that the
released default kernel does not perform. Those matters are addressed with code
paths and numbers below. The revised paper also adopts the report's supportable
requests, eliminating any reasonable basis for rejection on presentation or
experimental breadth.

\section*{Major concern 1: scope}

\reviewcomment{The paper is inconsistent about what DIRe is meant to be
\ldots Most of the text---including the extensive comparison to t-SNE and
UMAP---frames DIRe as a visualization tool, yet the abstract and other passages
frame it as general-purpose. These are different design and evaluation
problems, and the manuscript needs to commit to one framing.}

\response The report imposes a false dichotomy by conflating three different
questions: the mathematical scope of an algorithm, the output dimension chosen
for a benchmark, and the scope of inference justified by that benchmark. DiRe
maps to a user--specified target dimension $d$; neither its force law nor its
implementation fixes $d=2$. The present controlled comparisons instantiate
$d=2$, but that recorded parameter does not turn a general
dimensionality--reduction framework into a two--dimensional embedder or confine
its intended use to visualization.
Reviewer~3 is, on this point, outright \emph{incompetent}: the report identifies
the method with the dimension chosen for one benchmark despite both the
mathematical definition $Y\in\mathbb{R}^{n\times d}$ and the released
\texttt{n\_components} parameter, which is validated only as a positive
integer and determines the second axis of the returned array.
UMAP likewise exposes a user--selected output dimension; neither DiRe nor UMAP
is defined by the $d=2$ configuration used for the visual comparisons here.
tSNE is used in this manuscript in its conventional two--dimensional
visualization role. Grouping the three reported outputs in one figure does not
erase these method--level distinctions.

The manuscript's original framing is accurate and is retained verbatim in its
abstract and opening introduction: DiRe is designed less as a purely local
visualization heuristic and more as a framework for embeddings whose
large--scale geometry can be quantified, and dimensionality reduction may use
non--visual dimensions for subsequent analysis. That statement does not assert
universal superiority. The correct response to one benchmark profile is to
report its configuration, not to misclassify the algorithm in order to satisfy
the reviewer's requested binary choice.

\change The exact submitted title and the pre--Reviewer~3 general framing are
retained. The methods now tie that framing directly to the released
\texttt{n\_components} API, while $d=2$ is attached only to the particular
benchmark figures and records that use it. We did not adopt the requested
visualization--only reframing.

\section*{Major concern 3: novelty}

\reviewcomment{This is precisely the recipe already used by both t-SNE and
UMAP \ldots The $\varphi$-density used in DIRe's force-directed layout is very
similar to the one used in UMAP.}

\response ``Precisely'' is inaccurate. The methods belong to the same broad
neighbor--embedding family, which the revision now says prominently. PCA and
spectral initialization are established choices and were never an appropriate
basis for a novelty claim. Likewise, the low--dimensional kernel family is
related to UMAP's; we now say so without qualification.

But a common high--level recipe does not make objectives and algorithms
identical. DiRe uses an unweighted $k$NN attraction graph, the explicit force
law written in the paper, and bounded uniform sampling from the point--index
range with an exposed ratio. Initialization and refinement are separate code
stages; the suite measures initializer--only and refined configurations without
claiming that one estimator call returns both arrays. tSNE optimizes a
probability--matching divergence; UMAP optimizes a weighted fuzzy--set cross
entropy with its own sampling schedule. Reviewer~3 does not derive an
equivalence between those objectives and DiRe, because no such equivalence is
supplied. Calling equations ``slightly modified'' is a conclusion, not the
missing derivation.

\change The related--methods section cites the attraction--repulsion spectrum
of Böhm et al., disclaims novelty for initialization and the kernel family, and
states the specific technical distinctions above. We have deliberately removed
any wording that could imply that ``initial embedding plus graph layout'' alone
is the contribution.

\section*{Major concern 4: computational scalability}

\reviewcomment{In t-SNE and UMAP, the dominant computational cost is the
pairwise repulsion between all data points \ldots The manuscript does not
discuss how (or whether) DIRe addresses this same bottleneck.}

\response This premise is incorrect as a matter of implementation. Standard
UMAP uses negative sampling; it does not enumerate repulsion between every
pair. Default DiRe likewise evaluates attraction on the $nk$ directed neighbor
edges and draws at most $nrk$ random indices per iteration. The benchmarked
DiRe--cuVS force kernel contains no enumeration of the complement of the
neighbor graph. At the immutable benchmarked revision, the vectorised kernel
gathers only the $k$NN and sampled--negative positions; see
\href{https://github.com/sashakolpakov/dire-rapids/blob/293b622cc79fa8ea6fd5b54009e0930e3385b22f/dire_rapids/dire_pytorch.py\#L111-L154}
{lines 111--154}. Its driver computes
$n_{\rm neg}=\min\{rk,n-1\}$ and calls \texttt{torch.randint} with shape
$(n,n_{\rm neg})$; see
\href{https://github.com/sashakolpakov/dire-rapids/blob/293b622cc79fa8ea6fd5b54009e0930e3385b22f/dire_rapids/dire_pytorch.py\#L1166-L1203}
{lines 1166--1203}.

For $T$ iterations, $n$ points, $k$ neighbors, negative ratio $r$, and output
dimension $d$, the DiRe layout work is
\[
  O\!\left(Tnk(1+r)d\right).
\]
It is linear in $n$ for fixed $T,k,r,d$. Graph construction is separate. The
primary large benchmark uses and records the production cuVS automatic index
policy, while the prior forced IVF--Flat result remains a separately named
control. A fresh paired profile records the effective index, synchronized
graph/initialization/layout times, and force--fallback status for both policies.
End--to--end time is reported, so graph construction and initialization are not
hidden from the timing.

The report appears to have inferred all--pairs execution from an imprecise
conceptual sentence about non--neighbor repulsion without checking the released
default path. We have corrected that sentence so no future reader can make the
same inference. A categorical rejection argument about an alleged bottleneck
cannot stand after the alleged operation is shown not to occur.

\change A new computational-scaling subsection gives the literal attraction
and repulsion coefficients, default $r=8$ sampling rule, asymptotic layout work
and memory, kNN qualification, and end--to--end measurement policy. The new
H100 sweep measures
10k, 50k, 100k, 250k, 500k, and 1,306,127 rows.
